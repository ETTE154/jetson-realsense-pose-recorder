## 기준 구성

Jetson Orin NX 16GB, Ubuntu22.04, JetPack6.2.1/L4T36.4.7, CUDA12.6,
TensorRT10.3.0, Python3.10.12, OpenCV4.8.0, NumPy1.21.5.
D435i 펌웨어5.17.3.10, USB3.2, RGB-D640×480@30.
가속도63Hz·자이로200Hz, 프로젝트 로컬 librealsense v2.59.1 RSUSB.

## IMU 영상 저장 원복 근거

기존 26.827초/51.277초 녹화에서 원본 영상이 각각 최대11.867초/29.667초
반복됐습니다. 그동안 카메라·IMU의 CSV 이벤트는 계속 들어왔습니다.
파일 디코딩 손상보다 녹화 처리 적체로 판단했습니다.

IMU 그래프2개와 영상7개 순차 CPU 인코딩이 15fps의 66.7ms 예산을 넘었고
밀린 영상 루프가 새 입력을 늦게 읽었습니다. 그래프 벡터화와 입력 큐를 자주
읽는 수정을 적용했지만 90.055초 실험에서 평균115.5ms/프레임, 누락591개,
최대 적체66.2초가 관측됐습니다. 현 CPU 인코딩 구성으로 IMU 그래프 영상까지
유지할 수 있다고 판단하지 않았습니다. 메모리 고갈·카메라 고장을 입증한 것은 아닙니다.

v1.4.2는 입력 큐 개선과 성능 통계를 유지하고 IMU 그래프 렌더링과 별도
imu.mp4 인코딩을 활성 녹화 경로에서 제거했습니다. 합본은1280×960 4분할이며
원본 IMU CSV와 실시간 UI 그래프는 그대로입니다.

## 손·GPU에 대한 별도 검사

- 앞선8.082초 실녹화에서 실제 손 관절546행, 카메라242행, 가속도505행,
  자이로1,601행, Pose 프레임40행을 저장했습니다. 총2,934행이며 원본IMU
  2,106개를 UI 이력과 샘플 단위로 대조해 누락 없이 일치했습니다.
- YOLO→MediaPipe→RTMPose→EgoForce 전환과 모델별5종 MJPEG 각각
  연속3프레임의640×480 디코딩·프레임 순번 증가를 검사했습니다.
- 실제 손 입력에서 HALO의 cuda:0/FP16 파라미터와21점·24점 유한 좌표를
  확인했습니다. 두 입력의 워밍업 후 HALO 평균은 약96ms/80ms였으며
  별도 MediaPipe 손 검출 시간은 포함하지 않습니다.
